# CLAUDE.md – notes for Claude Code sessions

## Project
APC interview assistant. Browser captures meeting audio (getDisplayMedia system/tab audio), an energy VAD cuts speech into segments; the server transcribes them (OpenRouter STT), a fast model detects questions, and the answer model streams a short description + points using the user's profile/notes, the shared competency library and the user's private case study. Multi-user with an admin role.

## Layout
- `server.js` – wiring: migrations + storage check at start-up, `/health`, `/api/*` routers, static files.
- `lib/db.js` – Postgres pool and idempotent migration (users, sessions, competencies, documents, chunks with generated `tsvector`, usage). `lib/competencies.js` – seed list from the RICS QS&C pathway guide (Dec 2025).
- `lib/auth.js` – scrypt hashes, session token cookie (`tma_session`, SHA-256 stored), `loadUser` / `requireUser` / `requireAdmin`.
- `lib/storage.js` – Railway bucket via S3 client when `S3_BUCKET` is set, else `./data/uploads`.
- `lib/extract.js` – PDF (pdf-parse v2), DOCX (mammoth), PPTX (jszip, slides + speaker notes), text; audio types (`isAudio`, max 300 MB).
- Audio knowledge files: `lib/audio-notes.js` – uploads of MP3/M4A/WAV… (library or case study) are stored at once (`addAudioDocument`, `documents.source='audio'`, `status` processing/ready/failed, `progress`, `error`, `duration_s`, `cost`) and processed in a one-at-a-time background queue (`queueAudio`; `resumeAudioJobs()` at start-up restarts interrupted jobs): ffmpeg (`FFMPEG_PATH`, installed on Railway via `RAILPACK_DEPLOY_APT_PACKAGES=ffmpeg`; `/health` reports `audio`) finds pauses (`silencedetect`) and cuts ~8-minute 16 kHz mono MP3 pieces at pauses (`cutPoints`); each piece is transcribed (pref `knowledgeSttModel`, default `openai/whisper-large-v3`, RICS vocabulary + previous words as hints); the transcript is split into ~1800-word parts (`splitTranscript`) and organised by `NOTES_PROMPT` (pref `knowledgeModel`, default Haiku 5.5, thinking off, temperature 0.1; only what was said), then `NOTES_SUMMARY_PROMPT` gives title / summary / key terms; `assembleNotes()` = notes + full transcript with time ranges, saved as the document text and chunks (`saveAudioNotes`). Usage kind `knowledge`. Routes: `POST /documents/:id/retry`, `GET /documents/:id/notes` (Markdown, `?download=1`). UI helpers in `public/js/pages/uploads.js` (`docMeta`, `docActions`, notes reading view, `refreshWhileProcessing`).
- `lib/documents.js` – upload (bucket + chunks), Postgres full-text search (`searchKnowledge`: up to 4 case study + 5 library chunks). `lib/knowledge.js` – tokenizer and chunking.
- `lib/openrouter.js` – config, model list cache, `pickModel`, per-user `recordUsage` / `usageTotals`.
- `lib/routes/account.js` (setup, login, me, prefs, users), `lib/routes/library.js` (competencies, documents), `lib/routes/ai.js` (models, transcribe, detect, answer).
- Chat: `lib/routes/chat.js` (chats with `pinned` (list ordered pinned first), messages, streamed answers with numbered excerpts; trailer `{cost, sources:[{n, chunkId, documentId, doc, scope}], messageId, userMessageId, title}`; `editFrom` on a new message deletes that message and later ones first; `POST /chats/:id/suggestions` returns 3 follow-ups from the detect model plus `cost`). `chat_messages.cost` = reply cost plus its suggestions (usage kinds `chat` and `chat_extra`, both counted as Chat in `usageTotals`); the small cost under each reply is shown on the Chat page only, never on Live answers, `public/js/pages/chat.js` (list, thread, composer, document viewer; `placeComposer()` centres the composer on an empty chat wider than 640px; keyboard shortcuts Ctrl/⌘+Shift+O, Ctrl/⌘+K, Esc; redraws while streaming are throttled with requestAnimationFrame and cancelled when the stream ends), `public/js/markdown.js` (safe Markdown → tree, citations `[n]`). Viewer: `GET /api/documents/:id/view?chunks=` returns full text + ranges via `locateChunks` (`lib/knowledge.js`). `documents.text` holds the full text; older documents are backfilled from the bucket at start-up.
- `lib/decisions.js` – decision model (`DECISION_MODEL`, default `typesafe/jev-1.14`) on the OpenRouter Decisions API (`POST /api/alpha/decisions`, typed answers with probabilities, not text; not chat-completions). `detectWithJev` (is_question / needs_tidy), `routeQuestion` (competency, case study/library source, chat needs_documents). Every helper returns null on failure (4 s timeout) and callers fall back to the old behaviour. Per-user switch: pref `useDecisions` (default on). Detection: Jev decides; Haiku (`TIDY_PROMPT`) runs only when Jev says question + needs tidying. Search: `routedCounts` shifts case study/library counts, the likely competency's library chunks come first. Usage kinds: `detect`, `answer_extra` (counted as Live answers), `chat_extra` (Chat).
- `lib/prompt.js` – answer and detection prompts, filters. Answer format: `NONE` or `Q: …\nA:\n<description and/or - points>`; `buildSystemPrompt(style)` has rules + example per style (`points`, `brief`, `balanced` default, `detailed`; list in `public/js/format.js`). The client sends `style` with each answer request. Detect format: `QUESTION: …` or `NONE`.
- Dropdowns: every `<select class="select">` (`select-sm` for compact) is replaced at runtime by `enhanceSelect()` in `public/js/ui.js` (app-styled listbox, keyboard, search for long lists). The hidden native select keeps the value, so set `.value`, swap options and listen for `change` as usual; hide the `.dd` wrapper, not the select. No focus glows: focus shows as a primary-coloured border. On touch screens dropdowns don't focus their search box (no keyboard until tapped), and while open they follow page resizes and scrolls (`place()` / `placePop()`) instead of closing; they close on a tap outside or when their button leaves the screen.
- `combobox()` in `public/js/ui.js` – searchable select used for model pickers (search matches name, id and group, not price); `compact: true` for toolbars. `public/js/model-items.js` – model picker items and thinking-level helpers shared by Settings and the Live answers toolbar.
- `/api/answer` accepts `model`, `reasoning` and `style` in the request (validated), falling back to the user's saved prefs, so toolbar changes apply to the next question at once.
- Frontend (no build, plain ES modules): `public/index.html`, `public/css/app.css` (light/dark tokens), `public/js/main.js` (shell + hash router), `public/js/ui.js` (h(), icons, toasts, dialogs), `public/js/pages/*`. `public/js/icons.js` is generated by `npm run icons` from lucide-static (committed).
- Sidebar: `.app.rail` collapses it to icons with short labels (desktop only); `sidebarCollapsed` pref, and it collapses automatically on the Chat page (a toggle there only applies to that visit). Chat uses its own `chatModel` / `chatReasoning`, separate from the Live `answerModel` / `reasoning`.
- Voice mode (Chat page): `public/js/voice.js` – `startVoice()` creates the AudioContext inside the tap, opens the microphone only while voice mode is on, and uses `SpeechSegmenter` (`public/audio.js`; `startWindow` allows syllable gaps; `onSegment(samples, reason)` with `'pause'`/`'max'`). A pause (pref `voicePause`: short 0.6 s / normal 0.9 s / long 1.5 s; mock interviews always long) ends the turn; the whole turn is sent once to `POST /api/voice/transcribe` (pref `voiceSttModel`, default `openai/gpt-transcribe`, with RICS + competency vocabulary hints via `provider.options.openai/groq.prompt`, retried without hints on 400). No separate tidy step: `VOICE_STYLE` tells the reply model the message is speech-to-text. Voice replies use their own fast model (`voiceChatModel`, default `anthropic/claude-haiku-5.5`; `voiceReasoning`, default off) and start with a short first sentence. Replies are spoken sentence by sentence (`public/voice-text.js`: `speakable()`, `takeChunks()`; first chunk ≥12 chars, then ≥60) through two `<audio>` players (one plays, one preloads) streaming `GET /api/speak?t=&c=&m=` (OpenRouter `/audio/speech`; mp3 streamed through, PCM-only models wrapped as WAV, remembered per model). Both players go through an AnalyserNode; while the AI speaks, `BargeIn` (`public/audio.js`) compares the mic level with the AI's output level (learned echo ratio) so echo is ignored and real speech interrupts (pref `voiceInterrupt`); the last 0.5 s of mic audio is kept so the interrupting words are not lost. Tapping the orb also interrupts. Pref `voiceAutoSend` off shows the text for review. Voice: prefs `voiceModel` / `voiceName` (default `hexgrad/kokoro-82m` / `bm_george`). Usage kinds `voice_stt` and `voice_tts` → `voice` in `usageTotals` (plus `voiceTurns`); speech cost (estimated per character) is also added to the reply's cost (`takePendingVoiceCost`). The microphone stops when leaving Chat.
- Mock interview: `chats.mode` = `mock` (`POST /api/chats {mode:'mock'}`); `MOCK_SYSTEM` prompt (panel chair, one question at a time, short feedback, results on request). `POST /chats/:id/messages {start:true}` makes the panel speak first (no candidate message saved). The Search setting sets the focus (all, case study, library, one competency). No follow-up suggestions in mock chats.
- Phone keyboard: viewport meta has `interactive-widget=resizes-content` (Android shrinks the layout); `trackKeyboard()` in `public/js/main.js` sets `--app-h` from `visualViewport` (iOS) and `html.kb-open`, which hides the chat settings row on phones. The chat thread keeps the latest message in view when it is resized.
- Settings (`public/js/pages/settings.js`): sections Profile, Appearance, Live interview, Chat, Voice, Advanced (fast decisions, reset models), Usage & cost, Password. Each section = heading + cards of `row(label, hint, control)` (label left, control 320px right; stacked on phones except `.compact` switches/buttons). Sections expose `reset()` for "Reset all models". Model pickers (`combobox`) show one line: name + short price (`short` on items). Usage: total with a This month / All time switch and one line per category with a share bar. Tablet/phone: the section bar is a sticky row of scrolling pills.
- `public/js/pages/overlay.js` – floating answers window (Document Picture-in-Picture, pop-up fallback); `public/js/format.js` – answer text parser shared with the cards.
- Shared pure modules: `public/audio.js` (VAD, WAV), `public/models.js` (model lists, prices, stream trailer). `public/capture-worklet.js` – AudioWorklet.
- `test/` – `npm test` (node:test).

## Conventions
- No build step, no frontend framework. Build DOM with `h()`; never put user text in innerHTML.
- Never send the OpenRouter key to the browser. Model choices, profile and notes are read from the user's record on the server.
- Library: everyone reads, admins write. Case study documents: only the owner (not even admins) can list or open them.
- Keep answers to the set structure in the prompt; never let the model invent figures not in notes/documents.
- Claude Sonnet 5.5 on OpenRouter always reasons and reasoning tokens count toward `max_tokens`; keep it large.
- Answer stream ends with `COST_MARK` (`\u001e`) + `{cost, sources}`.
- `OPENROUTER_BASE_URL` can point at a mock server for local tests; `LOCAL_STORAGE_DIR` for local files.
- `[detect]` logs include a short snippet of speech (temporary, for tuning detection).

## Deploy
Railway: `web` service builds with Railpack (config in `railway.json`), `Postgres` service, bucket `documents`. Variables use references (`${{Postgres.DATABASE_URL}}`, `${{documents.BUCKET}}` …). Secrets live in Railway variables.
