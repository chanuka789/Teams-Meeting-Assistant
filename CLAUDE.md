# CLAUDE.md – notes for Claude Code sessions

## Project
APC interview assistant. Browser captures meeting audio (getDisplayMedia system/tab audio), an energy VAD cuts speech into segments; the server transcribes them (OpenRouter STT), a fast model detects questions, and the answer model streams a short description + points using the user's profile/notes, the shared competency library and the user's private case study. Multi-user with an admin role.

## Layout
- `server.js` – wiring: migrations + storage check at start-up, `/health`, `/api/*` routers, static files.
- `lib/db.js` – Postgres pool and idempotent migration (users, sessions, competencies, documents, chunks with generated `tsvector`, usage). `lib/competencies.js` – seed list from the RICS QS&C pathway guide (Dec 2025).
- `lib/auth.js` – scrypt hashes, session token cookie (`tma_session`, SHA-256 stored), `loadUser` / `requireUser` / `requireAdmin`.
- `lib/storage.js` – Railway bucket via S3 client when `S3_BUCKET` is set, else `./data/uploads`.
- `lib/extract.js` – PDF (pdf-parse v2), DOCX (mammoth), PPTX (jszip, slides + speaker notes), text.
- `lib/documents.js` – upload (bucket + chunks), Postgres full-text search (`searchKnowledge`: up to 4 case study + 5 library chunks). `lib/knowledge.js` – tokenizer and chunking.
- `lib/openrouter.js` – config, model list cache, `pickModel`, per-user `recordUsage` / `usageTotals`.
- `lib/routes/account.js` (setup, login, me, prefs, users), `lib/routes/library.js` (competencies, documents), `lib/routes/ai.js` (models, transcribe, detect, answer).
- Chat: `lib/routes/chat.js` (chats, messages, streamed answers with numbered excerpts; trailer `{cost, sources:[{n, chunkId, documentId, doc, scope}], messageId, title}`), `public/js/pages/chat.js` (list, thread, composer, document viewer), `public/js/markdown.js` (safe Markdown → tree, citations `[n]`). Viewer: `GET /api/documents/:id/view?chunks=` returns full text + ranges via `locateChunks` (`lib/knowledge.js`). `documents.text` holds the full text; older documents are backfilled from the bucket at start-up.
- `lib/prompt.js` – answer and detection prompts, filters. Answer format: `NONE` or `Q: …\nA:\n<description and/or - points>`; `buildSystemPrompt(style)` has rules + example per style (`points`, `brief`, `balanced` default, `detailed`; list in `public/js/format.js`). The client sends `style` with each answer request. Detect format: `QUESTION: …` or `NONE`.
- `combobox()` in `public/js/ui.js` – searchable select used for model pickers (search matches name, id and group, not price); `compact: true` for toolbars. `public/js/model-items.js` – model picker items and thinking-level helpers shared by Settings and the Live answers toolbar.
- `/api/answer` accepts `model`, `reasoning` and `style` in the request (validated), falling back to the user's saved prefs, so toolbar changes apply to the next question at once.
- Frontend (no build, plain ES modules): `public/index.html`, `public/css/app.css` (light/dark tokens), `public/js/main.js` (shell + hash router), `public/js/ui.js` (h(), icons, toasts, dialogs), `public/js/pages/*`. `public/js/icons.js` is generated by `npm run icons` from lucide-static (committed).
- Sidebar: `.app.rail` collapses it to icons with short labels (desktop only); `sidebarCollapsed` pref, and it collapses automatically on the Chat page (a toggle there only applies to that visit). Chat uses its own `chatModel` / `chatReasoning`, separate from the Live `answerModel` / `reasoning`.
- `public/js/pages/overlay.js` – floating answers window (Document Picture-in-Picture, pop-up fallback); `public/js/format.js` – answer text parser shared with the cards.
- Shared pure modules: `public/audio.js` (VAD, WAV), `public/models.js` (model lists, prices, stream trailer). `public/capture-worklet.js` – AudioWorklet.
- `test/` – `npm test` (node:test).

## Conventions
- No build step, no frontend framework. Build DOM with `h()`; never put user text in innerHTML.
- Never send the OpenRouter key to the browser. Model choices, profile and notes are read from the user's record on the server.
- Library: everyone reads, admins write. Case study documents: only the owner (not even admins) can list or open them.
- Keep answers to the set structure in the prompt; never let the model invent figures not in notes/documents.
- Claude Sonnet 5.5 on OpenRouter always reasons and reasoning tokens count toward `max_tokens`; keep it large.
- Answer stream ends with `COST_MARK` (`\u001e`) + `{cost, sources}`.
- `OPENROUTER_BASE_URL` can point at a mock server for local tests; `LOCAL_STORAGE_DIR` for local files.
- `[detect]` logs include a short snippet of speech (temporary, for tuning detection).

## Deploy
Railway: `web` service builds with Railpack (config in `railway.json`), `Postgres` service, bucket `documents`. Variables use references (`${{Postgres.DATABASE_URL}}`, `${{documents.BUCKET}}` …). Secrets live in Railway variables.
